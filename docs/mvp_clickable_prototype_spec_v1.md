# MVP Clickable Prototype Spec v1

## 目标

本文件定义 MVP 可点击原型应覆盖的路径与状态变化。

本阶段不创建真实原型文件，只定义：

- 起点
- 用户动作
- 系统反馈
- 页面状态变化
- 终点
- 禁止出现的误导行为

## 原型原则

1. 原型服务于解释工作流，而不是炫技。
2. 原型必须覆盖“从导入到多端草稿”的主链路。
3. 原型每条路径都必须体现 `draft / preview / not_sent` 语义。

## A. 第一次使用路径

### 路径目标

让第一次进入系统的用户，在最少步骤内完成导入并看到今日 Pulse。

### 路径定义

- 起点：
  - 首页 `empty state`
- 用户动作：
  1. 点击 `导入论文`
  2. 进入导入页
  3. 拖入文件或粘贴内容
  4. 点击 `开始识别`
  5. 进入导入预览
  6. 点击 `确认导入可导入记录`
  7. 进入导入完成页
  8. 点击 `查看今日 Pulse`
- 系统反馈：
  - 自动识别格式
  - 自动生成可导入 / warning / error 统计
  - 自动给出导入完成后的下一步建议
- 页面状态变化：
  - 首页 `empty`
  - 导入页 `default`
  - 导入页 `loading`
  - 导入预览 `success + warning`
  - 导入完成 `success`
  - 首页 / Pulse `success`
- 终点：
  - 首页显示今日 Research Pulse
- 禁止出现的误导行为：
  - 先要求用户选格式
  - 先要求用户配置导入规则
  - 导入完成后停在“成功提示”不引导下一步

## B. 每日使用路径

### 路径目标

让用户围绕今日工作推进，而不是围绕系统管理推进。

### 路径定义

- 起点：
  - 首页今日 Pulse
- 用户动作：
  1. 查看今日重点论文
  2. 点击某篇论文卡片
  3. 打开论文详情 drawer
  4. 更新阅读状态或下一步动作
  5. 点击 `保存进度`
  6. 返回首页
  7. 点击 `刷新今日 Pulse`
- 系统反馈：
  - drawer 内即时显示当前论文状态
  - 保存后更新状态
  - Pulse 刷新后可反映最新进度
- 页面状态变化：
  - 首页 `default`
  - Drawer `open`
  - Drawer `success`
  - 首页 `loading`
  - 首页 `success`
- 终点：
  - 首页显示新的今日 Pulse
- 禁止出现的误导行为：
  - 点击论文后跳走到复杂编辑页
  - 保存后无反馈
  - 把刷新结果表现成真实外部发送

## C. 导入问题处理路径

### 路径目标

让用户只处理问题记录，不被完整记录干扰。

### 路径定义

- 起点：
  - 导入预览页出现 warning / error
- 用户动作：
  1. 点击 `只看问题记录`
  2. 查看缺题名 / 缺年份 / 缺 DOI 等问题
  3. 对可导入记录继续点击 `确认导入可导入记录`
  4. 将问题记录留待稍后处理
- 系统反馈：
  - 问题记录单独聚焦
  - warning 与 error 区分明确
- 页面状态变化：
  - 导入预览 `warning + error`
  - 问题记录筛选视图 `warning`
  - 导入完成 `warning`
- 终点：
  - 可导入记录已进入系统，问题记录被清楚标记
- 禁止出现的误导行为：
  - 把 warning 当作失败
  - 要求用户一次性修完所有问题才能继续

## D. 渠道草稿路径

### 路径目标

让用户从同一份 Research Pulse 上下文生成多端草稿，但不误以为已经发送。

### 路径定义

- 起点：
  - Research Pulse 详情页
- 用户动作：
  1. 点击 `生成公众号摘要草稿`
  2. 查看 `draft / not_sent` banner
  3. 点击 `复制 Markdown`
  4. 返回 Pulse
  5. 点击 `生成桌面通知草稿`
  6. 点击 `复制 payload`
  7. 返回 Pulse
  8. 点击 `小程序详情预览`
  9. 点击 `复制 path` 或 `复制 share card`
- 系统反馈：
  - 各渠道页都显示状态 banner
  - 草稿页均可复制，但不触发真实发送
- 页面状态变化：
  - Pulse 详情 `success`
  - 公众号页 `draft + not_sent`
  - 桌面页 `draft + not_sent`
  - 小程序页 `preview`
- 终点：
  - 用户拿到三个渠道的可复制草稿 / 预览结果
- 禁止出现的误导行为：
  - “已发送成功”
  - “已推送成功”
  - “已发布到小程序”

## E. 小程序详情预览路径

### 路径目标

让用户或前端理解未来小程序详情结构，而不是伪装成真实小程序。

### 路径定义

- 起点：
  - 小程序详情预览页
- 用户动作：
  1. 切换 `detail_type tabs`
  2. 查看 `daily_pulse`
  3. 查看 `paper`
  4. 查看 `next_actions`
  5. 查看 `metadata_attention`
  6. 查看 `triage`
  7. 查看 `share-safe card`
  8. 复制 path placeholder
- 系统反馈：
  - path、share card、visibility notes 清晰变化
  - share-safe 说明始终可见
- 页面状态变化：
  - `preview`
  - `preview + warning`（当字段被裁剪时）
- 终点：
  - 用户能理解不同详情类型的结构
- 禁止出现的误导行为：
  - 微信登录入口
  - 小程序码
  - 支付或订阅消息

## 原型演示顺序建议

建议后续 clickable prototype 演示顺序为：

1. 第一次使用
2. 每日使用
3. 导入问题处理
4. 渠道草稿
5. 小程序详情预览

这样可以先展示主链路，再展示边界与例外处理。

## 原型验收标准

Design-3 之后的 clickable prototype，如果不满足以下条件，就不算合格：

1. 首页起点明确。
2. 导入路径闭环清楚。
3. 论文进度 drawer 流程闭环清楚。
4. 三个渠道输出都保持草稿/预览边界。
5. 没有任何真实平台接入暗示。
