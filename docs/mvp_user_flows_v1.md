# MVP User Flows v1

## 目标

本文件定义 China-first Research Pulse MVP 的关键用户流程，确保后续 wireframe、前端实现和 demo 脚本都围绕真实科研动作而不是后台对象展开。

## Flow A：第一次使用

### 用户目标

第一次把论文放进系统，并快速知道今天该从哪里开始。

### 用户路径

1. 进入系统首页
2. 看到拖入入口或导入按钮
3. 拖入 PDF 文件夹、CSV，或粘贴 BibTeX / RIS / CSL JSON
4. 系统自动识别格式并生成导入预览
5. 用户确认可导入记录
6. 系统完成导入并自动生成今日 Pulse

### 系统自动完成的事情

- 识别格式
- 归一化字段
- 标记 warnings / errors
- 识别可提交记录
- 导入后构建初始 progress 状态
- 生成今日 Pulse 草稿

### 用户只处理的事情

- 确认导入
- 处理少量问题记录

### 预期结果

用户首次进入后，不需要学会文献系统，也能看到：

- 哪些论文已进入系统
- 哪些记录待补全
- 今天优先看哪些

## Flow B：每日使用

### 用户目标

每天快速回到研究工作，不被系统管理本身打断。

### 用户路径

1. 打开首页
2. 阅读今日 Research Pulse
3. 进入“今日重点论文”或“下一步动作”
4. 更新一两篇论文的阅读状态或研究阶段
5. 补充 next action
6. 视需要生成公众号摘要草稿

### 首页应直接回答

- 今天哪几篇最值得处理
- 哪些论文还在精读或分析中
- 哪些记录需要补元数据
- 哪些新导入论文还没筛选

### 预期结果

用户每日流程更像“推进研究”，而不是“维护数据库”。

## Flow C：导师 / 课题组场景

### 用户目标

快速了解高优先级论文与本周推进情况，并方便复制摘要或行动清单。

### 用户路径

1. 打开首页或论文进度页
2. 查看高优先级论文
3. 查看 next action 和阅读进展
4. 生成公众号摘要草稿或复制文本
5. 将结果发给学生、课题组或用于周会准备

### 系统价值

- 自动聚合重点论文
- 自动突出下一步动作
- 自动把同一套上下文转成摘要草稿

### 预期结果

导师不必手动从文献库挑选材料，而是直接看到“可汇报内容”。

## Flow D：元数据补全场景

### 用户目标

只处理真正有问题的记录，不被完整记录打扰。

### 用户路径

1. 从首页“元数据待补全”进入
2. 看到问题论文列表
3. 只处理缺作者 / 年份 / DOI / 来源等记录
4. 完成后回到正常阅读或筛选流程

### 系统自动完成的事情

- 自动把问题记录聚合出来
- 用中文说明缺失项
- 区分“可导入但建议补全”和“暂不可导入”

### 预期结果

用户只处理例外，不需要在全量论文中手工找问题。

## Flow E：小程序详情场景

### 用户目标

从摘要或通知进入后，能快速看到精简但足够用的详情。

### 用户路径

1. 从未来的小程序入口、草稿链接或 path placeholder 进入
2. 打开某个详情类型：
   - 今日 Pulse
   - 单篇论文
   - 下一步动作
   - 元数据待补全
   - 新导入待筛选
3. 查看卡片、摘要、建议动作
4. 再决定是否进入更完整的工作台

### 预期结果

小程序详情承担“快速理解与继续操作”的角色，而不是完整系统的复制品。

## Flow F：导入后立即推进阅读

### 用户目标

导入不是终点，导入后立即形成工作优先级。

### 用户路径

1. 导入完成
2. 系统把部分论文自动放进：
   - 待读
   - 待筛选
   - 待补全
3. 用户从首页看到建议处理对象
4. 把一篇论文标成略读中或精读中
5. 填写下一步动作

### 预期结果

导入与研究推进之间没有断层。

## Flow G：从草稿到多端预览

### 用户目标

用同一套 Research Pulse 上下文生成不同渠道的草稿，不重复整理。

### 用户路径

1. 生成 Research Pulse 草稿
2. 生成公众号摘要草稿
3. 生成桌面通知草稿
4. 生成小程序详情预览

### 统一边界

- 都是草稿或预览
- 都不是真实发送
- 都基于同一套论文与进度上下文

### 预期结果

用户感受到的是“一份研究上下文，多种表现形式”，而不是多个孤立系统。

## 流程设计原则总结

所有 MVP 用户流程都应满足：

1. 用户先看到结论，再看结构。
2. 系统优先自动分类，用户只处理决策。
3. 用户处理的是科研动作，不是技术对象。
4. 每条流程都尽量在少步骤内闭环。
5. 所有草稿与预览都必须明确标识状态，不伪装成真实投递。
