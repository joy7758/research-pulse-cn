Implement Phase 56 only: group workspace conversion time-window filtering admin web shell v1.

Hard boundaries for this phase:
- Do not add source file sharing.
- Do not add local attachment sharing, note-file sharing, or cloud attachment sync.
- Do not add real-time collaboration or live multi-user editing.
- Do not add new delivery channels.
- Do not add desktop or mini UI work in this phase.
- Do not add a generic end-user login/session system.
- Do not add campaign/broadcast/referral behavior.
- Do not add third-party browser analytics scripts.
- Do not add AI attribution, AI summarization, or LLM-based dashboard copy.
- Do not create a new frontend app; extend the existing group-workspace-admin-web only.
- Do not weaken existing auth boundaries.
- Do not replace the modular monolith backend architecture.

Primary goal:
Extend the existing internal group-workspace admin shell with read-only time-window and dimension filters over the already implemented overview + drilldown endpoints.

This phase should make the repository suitable for:
- changing the time window of global conversion overview/drilldown
- changing the time window of workspace conversion overview/drilldown
- filtering by share_kind / access_mode / event_type / outcome where supported
- reviewing recent activity with explicit limit controls
- keeping the shell operator-readable, compact, and strictly read-only

Architectural intent:
- Reuse existing apps/group-workspace-admin-web.
- Reuse existing read-only backend endpoints.
- Prefer frontend-only work.
- If backend filter support is incomplete or inconsistent, add only tiny read-only compatibility fixes.
- No source-file semantics are exposed anywhere.

Required changes:

1. Reuse existing app only
Work inside:
- apps/group-workspace-admin-web

Requirements:
- do not create a new frontend app
- preserve current workspace list/detail/member/paper/share-grant/conversion-overview/drilldown behavior

2. Existing admin auth boot flow remains unchanged
Requirements:

- continue query/fragment token ingestion and immediate URL cleanup

  - localStorage
  - sessionStorage
  - cookies
- reuse existing API base URL handling

3. API client extension
Extend the existing typed API client.

Required filterable calls:
- GET /admin/group-workspace-conversion-overview
- GET /admin/group-workspace-conversion-drilldown
- GET /admin/group-workspaces/{workspace_id}/conversion-overview
- GET /admin/group-workspaces/{workspace_id}/conversion-drilldown

Add typed filter input model such as:
- ConversionFilterInput

Minimum fields:
- dateFrom nullable
- dateTo nullable
- shareKind nullable
- accessMode nullable
- eventType nullable
- outcome nullable
- limit nullable

Requirements:
- keep network logic out of React components
- attach bearer token from in-memory state only
- build query params deterministically
- return structured error objects suitable for UI display

Requirements:

6. Required filter behavior
Global view:
- date_from/date_to affects:
  - global conversion overview
  - global conversion drilldown
- optional share_kind/access_mode/event_type/outcome affects:
  - drilldown endpoint directly
  - overview when backend supports it cleanly

Workspace view:
- date_from/date_to affects:
  - workspace conversion overview
  - workspace conversion drilldown
- optional share_kind/access_mode/event_type/outcome affects:
  - workspace drilldown directly
  - workspace overview when backend supports it cleanly

Limit:
- controls recent lists in drilldown reads where backend supports it
- keep a compact default such as 20
