Implement Phase 58 only: result share grant / alias admin web shell v1.

Hard boundaries for this phase:
- Do not add source file sharing.
- Do not add local attachment sharing, note-file sharing, or cloud attachment sync.
- Do not add real-time collaboration or live multi-user editing.
- Do not add new delivery channels.
- Do not add desktop or mini UI work in this phase.
- Do not add a generic end-user login/session system.
- Do not add campaign/broadcast/referral behavior.
- Do not add third-party browser analytics scripts.
- Do not add AI attribution, AI summarization, or LLM-based dashboard copy.
- Do not create a new frontend app; extend the existing group-workspace-admin-web only.
- Do not weaken existing auth boundaries.
- Do not replace the modular monolith backend architecture.

Primary goal:
Extend the existing internal group-workspace admin shell with read-only per-share drilldown dashboards for:
1. ResultShareGrant
2. ResultShareAlias

This phase should make the repository suitable for:
- opening a specific share grant drilldown
- opening a specific alias drilldown
- reviewing direct event counts, aliases, recent events, and direct collect records
- keeping grant-level vs alias-level attribution explicit
- preparing a later richer per-share operator dashboard without exposing raw files

Architectural intent:
- Reuse existing apps/group-workspace-admin-web.
- Reuse existing read-only backend endpoints only:
  - GET /admin/result-share-grants/{grant_id}/conversion-drilldown
  - GET /admin/result-share-aliases/{alias_id}/conversion-drilldown
- Keep token handling exactly as the current in-memory admin shell.
- Keep the dashboard compact, operator-readable, and explicitly safe.
- No source-file semantics are exposed anywhere.
