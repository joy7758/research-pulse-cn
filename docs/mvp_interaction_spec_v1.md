# MVP Interaction Spec v1

## 目标

本文件定义 MVP 页面之间的交互规则，保证后续实现不会把产品做成复杂工具集合。

## 总原则

### 1. 每页一个主动作

交互上必须让用户一眼知道当前页最重要的下一步。

判断标准：

- 页面上只有一个视觉最强主按钮
- 主按钮必须对应当前页最自然的推进动作
- 次动作不能和主动作同级抢占注意力

### 2. 默认先显示结果，再允许深入

用户第一眼先看到：

- 今天的结论
- 当前状态
- 能否继续

只有在需要时才进入：

- 详情 drawer
- payload preview
- 问题记录列表

### 3. 复杂性放在展开层

优先级：

1. 首屏摘要
2. 卡片或列表
3. 侧栏 / drawer
4. payload preview

## 导入交互

### 目标

让用户尽快进入导入预览，而不是先配置导入规则。

### 规则

1. 用户拖入或粘贴后，不先要求选格式。
2. 系统先自动识别。
3. 如果识别失败，再显示支持格式说明。
4. 进入预览后，用户只需要决定是否导入可提交记录。

### 不允许的交互

- 先选择“这是 RIS / BibTeX / CSL JSON”
- 进入复杂字段映射面板
- 先设置导入策略再允许预览

## 预览交互

### 目标

让用户在最短时间内知道：

- 哪些能导
- 哪些有 warning
- 哪些不能导

### 规则

1. 先显示统计摘要。
2. 再显示记录列表。
3. 问题记录要能单独筛出。
4. 不可导入记录默认不参加主确认动作。

### 用户动作顺序

1. 看总数
2. 看问题数
3. 确认导入可导入记录

## 进度更新交互

### 目标

用户处理论文时，不要跳出主工作流。

### 规则

1. 从论文卡片点击进入 `PaperDetailDrawer`。
2. 在 drawer 内完成阅读状态、研究阶段、优先级、next action 更新。
3. 保存后停留当前列表上下文，不强制跳页。

### 建议默认动作

- 从首页卡片进入 drawer
- 从论文进度页进入 drawer
- 保存后列表即时反映状态变化

## Drawer 打开与关闭

### 打开

- 点击论文卡片
- 点击“查看详情”
- 点击问题记录中的论文条目

### 关闭

- 主动点击关闭
- 保存成功后可保持打开，也可按产品策略轻提示不自动关闭

### 不允许

- 未提示地丢失用户输入
- 关闭后用户回不到原列表上下文

## 复制交互

### 适用页面

- 公众号摘要草稿页
- 桌面通知草稿页
- 小程序详情预览页

### 规则

1. 复制动作必须直接说明复制什么。
2. 复制成功提示只能是“已复制”，不能暗示已发送。
3. 复制动作属于次流程，不应抢走页面主状态说明。

### 合法示例

- 已复制 Markdown
- 已复制 payload
- 已复制分享卡片

### 非法示例

- 已发送成功
- 已推送成功

## Payload Preview 交互

### 目标

让调用方或前端未来接入时能理解结构，但不把页面做成开发者调试台。

### 规则

1. 先显示人类可读的内容。
2. payload preview 默认折叠或下沉到次级区域。
3. 对 share-safe 裁剪要有清晰说明。

### 不允许

- 首屏直接显示原始 JSON 为主内容
- 暴露 raw_source_payload
- 暴露调试字段

## Warning / Error 处理

### Warning

含义：

- 可以继续
- 但建议用户注意某些问题

规则：

- warning 先说“是否还能继续”
- 再说“建议处理什么”

### Error

含义：

- 当前动作不能继续

规则：

- error 必须给出下一步建议
- 不展示技术堆栈

## 空状态处理

### 规则

1. 空状态必须告诉用户现在可以做什么。
2. 空状态要配合当前页主动作。
3. 不允许只是空白容器。

### 示例

- 首页无 Pulse：先导入论文或生成今日 Pulse
- 论文进度为空：先导入论文
- 下一步动作为空：从重点论文中补充一条

## `draft / preview / not_sent` 展示规则

### 公众号

- 页面首屏必须显示 `draft / not_sent`
- 不允许任何“发送成功”暗示

### 桌面

- 页面首屏必须显示 `draft / not_sent`
- 不允许任何“已推送”暗示

### 小程序

- 页面首屏必须显示 `preview`
- 同时显示 `share-safe` 或 `visibility notes`

## Share-safe 规则

### 当 `share_safe=true`

必须隐藏：

- raw source payload
- 用户私有笔记全文
- 调试字段
- 内部标识符细节

### 交互要求

- 用户能看到“已按 share-safe 规则裁剪”
- 但不需要理解技术实现

## 键盘与可访问性原则

本阶段不做实现，但需要固定原则：

1. 主动作必须可通过键盘焦点快速触达。
2. Drawer 打开后焦点应落在标题或首个可编辑字段。
3. 复制按钮、关闭按钮、保存按钮应有清晰文案。
4. badge、warning、error 不能只靠颜色表达。

## 不让用户理解技术细节的规则

以下技术复杂度不能成为用户主流程前置条件：

- 导入格式差异
- schema 名称
- payload 结构
- preview token
- share-safe redaction 实现方式
- 真实微信、桌面、小程序平台接口差异

用户只需要理解：

- 能不能继续
- 下一步是什么
- 当前结果是不是草稿或预览

## 交互验收标准

后续任何 wireframe 或前端实现，如果不满足以下条件，就不算通过：

1. 首屏能看懂当前页最重要任务。
2. 每页只有一个主动作。
3. warning 和 error 可区分，且都有下一步建议。
4. draft / preview / not_sent 明确可见。
5. 复制、预览、详情不会被误解为真实投递或真实发布。
