Implement Phase 11 only: official-account provider boundary v1.

Hard boundaries for this phase:
- Do not add real WeChat OAuth login.
- Do not add Mini Program frontend code.
- Do not add customer-facing UI.
- Do not add real external send by default.
- Do not make test/dev environments require live WeChat credentials.
- Do not weaken existing admin auth, internal service auth, device-token sync auth, or mini-read auth.
- Do not reintroduce WeChat as a generic DeliveryJob channel.
- Do not replace the current modular monolith architecture.

Primary goal:
Move the official-account path from "reserve only" to "provider-ready dry-run dispatch + inbound callback boundary".

This phase should make the backend suitable for:
- future real official-account provider activation
- safe dry-run dispatch of digest publication jobs
- inbound official-account callback ingestion
- official-account subscribe/unsubscribe state updates on existing bindings
- ops/admin inspection of provider readiness and callback events

Required changes:

1. Official-account provider settings and boundary
Add provider-facing settings, with safe defaults.

At minimum:
- official_account_provider_mode enum/string with values [disabled, dry_run]
- wechat_official_app_id
- wechat_official_app_secret
- wechat_official_callback_token
- wechat_official_callback_aes_key
- official_account_callback_enabled bool
- official_account_default_mini_program_app_id nullable
- official_account_default_article_base_url nullable
- official_account_dispatch_timeout_seconds

Requirements:
- default mode must be disabled or dry_run-safe
- do not require live credentials for tests
- document all settings clearly
- do not store secrets in repo
- keep the provider contract future-friendly for real integration in a later phase

2. Official-account callback event persistence
Add an OfficialAccountCallbackEvent model/table.

Required fields:
- id UUID pk
- app_id nullable
- to_user_name nullable
- from_openid nullable
- msg_type nullable
- event_type nullable
- event_key nullable
- event_time nullable
- dedupe_key string unique
- signature_valid bool
- payload_format enum [xml, json, unknown]
- raw_payload text
- parsed_payload json nullable
- processing_status enum [accepted, processed, ignored, duplicate, failed]
- processing_note nullable
- linked_binding_id nullable FK to WeChatIdentityBinding
- created_at
- processed_at nullable

Requirements:
- keep schema production-friendly
- dedupe repeated callbacks
- persist raw payload even when parsing fails
- use minimal parsing only for fields needed in v1

Constraints:

4. OfficialAccountPublisher interface
Introduce a clear provider boundary.

Requirements:
- add an OfficialAccountPublisher interface/service
- add DryRunOfficialAccountPublisher implementation
- optionally add DisabledOfficialAccountPublisher implementation
- do not perform real outbound network calls in this phase
- provider output should be based on:
  - DigestPublicationJob
  - PulseDigestIssue
  - PulseDigestItems
  - WeChatIdentityBinding
- render a provider-ready payload containing:
  - title
  - summary
  - highlights
  - landing metadata
  - binding summary
  - provider contract metadata
- keep payload transport-neutral enough to support a later real provider integration
- do not hardcode a final irreversible assumption about eventual transport shape

5. Dispatch flow for publication jobs
Add a real dispatch step, but dry-run only in this phase.

Required endpoints:
- POST /admin/digest-publication-jobs/{publication_job_id}/dispatch
- GET /admin/digest-publication-attempts
- GET /admin/official-account/provider-status
- GET /admin/official-account/callback-events

Behavior:
- operator and super_admin can dispatch and inspect
- viewer cannot
- dispatch must:
  - load the publication job
  - validate it is eligible for dispatch
  - create a DigestPublicationAttempt row
  - invoke the publisher boundary
  - update the publication job payload/status accordingly
- in dry_run mode:
  - no external send occurs
  - publication job should end in previewed or prepared-previewed state, but not sent
  - attempt status should be previewed
- in disabled mode:
  - return a controlled failure or conflict
  - create no fake success
- dispatch should be idempotent where practical for already previewed content
- list endpoints should support basic filtering where practical:
  - status
  - provider_mode
  - issue_date
  - user_id

6. Inbound callback endpoints
Add official-account callback ingress endpoints.

Required endpoints:
- GET /integrations/wechat/official-account/callback
- POST /integrations/wechat/official-account/callback

Behavior:
- these endpoints are not protected by admin auth; they are provider ingress endpoints
- verify request signature using settings when callback handling is enabled
- GET should support verification/echo-style handshake behavior
- POST should:
  - persist raw payload
  - verify signature
  - parse minimal payload fields
  - dedupe repeated events
  - record processing status
- supported v1 callback handling:
  - subscribe
  - unsubscribe
  - scan or similar event only if trivial to support cleanly; otherwise ignore with note
- if a matching WeChatIdentityBinding exists by:
  - channel_type = official_account
  - app_id
  - openid
  then update:
  - subscribed
  - subscribed_at
  - unsubscribed_at
  - last_seen_at
  - bind_state when appropriate
- if no binding exists:
  - persist event
  - do not auto-create a user binding
  - document this clearly as deferred until future binding flows
