# MVP Component Visual Rules v1

## 目标

本文件把 Design-2 的组件清单进一步转成视觉层规格。

本文件不写实现代码，只定义：

- 视觉目的
- 信息优先级
- 推荐布局
- 颜色语义
- 状态样式
- 主动作样式
- 禁止项

## 1. AppShell

- 视觉目的：
  - 提供稳定、低干扰的工作台框架
- 信息优先级：
  - 先主内容，再导航，再辅助信息
- 推荐布局：
  - 左窄、中宽、右按需展开
- 颜色语义：
  - 页面背景轻，内容区域清晰分层
- 状态样式：
  - loading 时主内容区有清楚占位
- 主动作样式：
  - 不承担主动作
- 禁止项：
  - 复杂仪表盘式装饰
- 中文文案注意事项：
  - 不用“控制台”“总览后台”

## 2. LeftNav

- 视觉目的：
  - 提供稳定定位感
- 信息优先级：
  - 当前页面高于其他导航项
- 推荐布局：
  - 图标可选，文字为主
- 颜色语义：
  - 当前项明确，其他项保持克制
- 状态样式：
  - active、hover、collapsed
- 主动作样式：
  - 不承担主按钮，只承担导航切换
- 禁止项：
  - 多级深层嵌套导航
- 中文文案注意事项：
  - 一级导航名称必须短

## 3. TopStatusBar

- 视觉目的：
  - 在首屏交代页面身份与当前状态
- 信息优先级：
  - 页面标题 > 状态语义 > 时间信息
- 推荐布局：
  - 左侧标题，右侧主动作
- 颜色语义：
  - 状态文字可带轻提示色，但不盖过标题
- 状态样式：
  - `draft / preview / not_sent / loading`
- 主动作样式：
  - 当前页唯一主动作可落在这里
- 禁止项：
  - 放置大量全局按钮
- 中文文案注意事项：
  - 状态词必须完整展示，不只用 icon

## 4. PulseSummaryCard

- 视觉目的：
  - 首页快速判断今日情况
- 信息优先级：
  - 数量结论 > 类别名称 > 辅助说明
- 推荐布局：
  - 小卡片并排或矩阵
- 颜色语义：
  - 用轻语义色，不做数据大屏
- 状态样式：
  - empty、warning、default
- 主动作样式：
  - 点击进入对应列表
- 禁止项：
  - 大红大绿数字牌
- 中文文案注意事项：
  - 先说事项，再说数量

## 5. PulseSection

- 视觉目的：
  - 组织结构化 section 内容
- 信息优先级：
  - section 标题 > section 描述 > item
- 推荐布局：
  - 标题上方，列表或卡片下方
- 颜色语义：
  - 各 section 可有轻分层，但不可像不同产品模块
- 状态样式：
  - empty 时保留 empty reason
- 主动作样式：
  - section 内主动作不要超过一个
- 禁止项：
  - section 标题过长
- 中文文案注意事项：
  - 使用工作导向词，不用抽象术语

## 6. PaperCard

- 视觉目的：
  - 让用户快速扫读论文并决定是否点击
- 信息优先级：
  - 标题 > 状态 / 优先级 > 来源信息 > next action / warning
- 推荐布局：
  - 标题单独占行，元信息二级显示
- 颜色语义：
  - 依赖 badge 和少量强调，不靠整卡染色
- 状态样式：
  - selected、warning、default
- 主动作样式：
  - 点击卡片打开详情 drawer
- 禁止项：
  - 把每个字段都当主信息平铺
- 中文文案注意事项：
  - 标题允许换行，不应被粗暴截断

## 7. PaperProgressBadge

- 视觉目的：
  - 快速标识阅读状态或研究阶段
- 信息优先级：
  - 一眼识别优先于装饰
- 推荐布局：
  - 小 badge 或 pill
- 颜色语义：
  - 各状态应区分，但不造成彩虹化页面
- 状态样式：
  - `待读 / 略读中 / 精读中 / 已读`
- 主动作样式：
  - 无
- 禁止项：
  - 只靠颜色区分
- 中文文案注意事项：
  - 必须显示中文状态词

## 8. PriorityBadge

- 视觉目的：
  - 明确论文优先级
- 信息优先级：
  - urgent > high > normal > low
- 推荐布局：
  - 与阅读状态 badge 相邻但不混淆
- 颜色语义：
  - `urgent / high` 可更明显
  - 但页面整体仍保持低干扰
- 状态样式：
  - 四档明显可辨
- 主动作样式：
  - 无
- 禁止项：
  - urgent/high 让整卡或整页变成警报界面
- 中文文案注意事项：
  - 优先级文案短且明确

## 9. MetadataWarningBadge

- 视觉目的：
  - 提醒需要补全元数据
- 信息优先级：
  - “建议补全”高于“错误氛围”
- 推荐布局：
  - 与元信息或卡片尾部相邻
- 颜色语义：
  - warning 语义，但偏温和
- 状态样式：
  - one-line summary + 可展开详情
- 主动作样式：
  - 点击看详情或问题说明
- 禁止项：
  - 做成严重故障标签
- 中文文案注意事项：
  - 用“建议补全”，少用“失败”

## 10. NextActionCard

- 视觉目的：
  - 把下一步动作从论文内容里抽出来
- 信息优先级：
  - 动作内容 > 关联论文 > 优先级
- 推荐布局：
  - 单卡短句，动词开头
- 颜色语义：
  - 轻强调，避免事项墙压迫
- 状态样式：
  - default、warning
- 主动作样式：
  - 继续处理
- 禁止项：
  - 变成长篇任务管理器
- 中文文案注意事项：
  - 动词明确，尽量一句话

## 11. ImportDropzone

- 视觉目的：
  - 降低首次导入门槛
- 信息优先级：
  - 先看见可拖入，再看支持内容
- 推荐布局：
  - 大块浅边框容器，视觉友好
- 颜色语义：
  - 中性、可接近
- 状态样式：
  - idle、drag_over、loading、error
- 主动作样式：
  - `开始识别`
- 禁止项：
  - 工程感过强的上传框
- 中文文案注意事项：
  - 明确说明“拖入或粘贴即可”

## 12. PasteImportPanel

- 视觉目的：
  - 接住不走文件上传的导入方式
- 信息优先级：
  - 可粘贴内容说明 > 输入区本身
- 推荐布局：
  - 与拖拽区并列或上下排列
- 颜色语义：
  - 中性
- 状态样式：
  - empty、filled、error
- 主动作样式：
  - `开始识别`
- 禁止项：
  - 大段技术格式说明抢占视线
- 中文文案注意事项：
  - 支持格式提示应短

## 13. ImportPreviewTable

- 视觉目的：
  - 让用户快速判断哪些可导、哪些不可导
- 信息优先级：
  - title / can_commit / warning / error
- 推荐布局：
  - 轻表格或伪表格
- 颜色语义：
  - 通过状态色辅助，不靠整行高饱和色
- 状态样式：
  - normal、warning、error
- 主动作样式：
  - `确认导入可导入记录`
- 禁止项：
  - 看起来像数据库调试表
- 中文文案注意事项：
  - 表头用用户能懂的中文字段

## 14. ImportIssueList

- 视觉目的：
  - 把问题集中解释清楚
- 信息优先级：
  - 问题描述 > 记录编号 > 建议动作
- 推荐布局：
  - 列表
- 颜色语义：
  - warning 与 error 区分清楚
- 状态样式：
  - warning、error、empty
- 主动作样式：
  - 查看问题记录
- 禁止项：
  - 输出技术异常对象
- 中文文案注意事项：
  - 每条都应包含下一步建议

## 15. PaperDetailDrawer

- 视觉目的：
  - 在不跳页的情况下集中处理单篇论文
- 信息优先级：
  - 标题与基础信息 > 可编辑状态 > next action > notes > warnings
- 推荐布局：
  - 自上而下，编辑区分组明确
- 颜色语义：
  - 以 surface 为主，warning 局部提示
- 状态样式：
  - open、loading、error
- 主动作样式：
  - `保存进度`
- 禁止项：
  - 塞入过多二级系统功能
- 中文文案注意事项：
  - “保存进度”比“保存修改”更贴业务

## 16. DraftStateBanner

- 视觉目的：
  - 明确告诉用户当前只是草稿或预览
- 信息优先级：
  - 状态词 > 状态解释 > 后续动作建议
- 推荐布局：
  - 页面首屏显著位置
- 颜色语义：
  - `draft / preview / not_sent` 各自稳定区分
  - 不使用 success 语义
- 状态样式：
  - draft、preview、not_sent
- 主动作样式：
  - 不承担主按钮，但可配合复制动作
- 禁止项：
  - 隐藏状态，只让用户猜
- 中文文案注意事项：
  - 必须完整写出“草稿”“预览”“未发送”

## 17. CopyActionBar

- 视觉目的：
  - 将复制类动作整理成稳定的次级操作条
- 信息优先级：
  - 复制主对象 > 复制次对象
- 推荐布局：
  - 页面下方或状态区下方一排按钮
- 颜色语义：
  - 主复制按钮更明确，其余克制
- 状态样式：
  - default、disabled、copied_hint
- 主动作样式：
  - 在当前页只有一个复制主按钮最强
- 禁止项：
  - 多个按钮一样强
- 中文文案注意事项：
  - 直接说“复制什么”

## 18. PayloadPreviewPanel

- 视觉目的：
  - 呈现结构化数据，但不抢主内容
- 信息优先级：
  - 人类可读摘要 > payload 结构
- 推荐布局：
  - 次级面板、折叠区或分栏次侧
- 颜色语义：
  - 中性、安静、可复制
- 状态样式：
  - preview、warning
- 主动作样式：
  - `复制 payload`
- 禁止项：
  - 像开发者调试台
- 中文文案注意事项：
  - 说明这是“可复制数据预览”

## 19. ShareCardPreview

- 视觉目的：
  - 预览用户未来可能分享的内容缩略
- 信息优先级：
  - title > summary > path
- 推荐布局：
  - 小卡片
- 颜色语义：
  - 干净克制
- 状态样式：
  - preview
- 主动作样式：
  - `复制 share card`
- 禁止项：
  - 做成营销海报样式
- 中文文案注意事项：
  - 短、稳、可信

## 20. MiniProgramPathPreview

- 视觉目的：
  - 告知小程序路径占位
- 信息优先级：
  - path 本身 > 说明文字
- 推荐布局：
  - 与 share card 并列或其下方
- 颜色语义：
  - 中性
- 状态样式：
  - preview
- 主动作样式：
  - `复制 path`
- 禁止项：
  - 暗示 path 已真实可访问
- 中文文案注意事项：
  - 强调“占位路径”

## 21. EmptyState

- 视觉目的：
  - 提供方向，不让页面落空
- 信息优先级：
  - 空状态结论 > 下一步建议
- 推荐布局：
  - 居中或主内容区显著卡片
- 颜色语义：
  - 中性偏温和
- 状态样式：
  - empty
- 主动作样式：
  - 直接引导到下一步
- 禁止项：
  - 只有“暂无数据”
- 中文文案注意事项：
  - 必须告诉用户下一步做什么

## 22. WarningState

- 视觉目的：
  - 表示可以继续，但有问题要注意
- 信息优先级：
  - 是否可继续 > 具体问题 > 建议动作
- 推荐布局：
  - 横向 banner 或纵向说明块
- 颜色语义：
  - 温和 warning
- 状态样式：
  - warning
- 主动作样式：
  - 继续主流程或处理问题
- 禁止项：
  - 做成故障报警
- 中文文案注意事项：
  - 明确“仍可继续”

## 23. ErrorState

- 视觉目的：
  - 表示当前动作需要修正
- 信息优先级：
  - 错误结论 > 重试或返回
- 推荐布局：
  - 独立容器，减少噪音
- 颜色语义：
  - error 明确但局部
- 状态样式：
  - error
- 主动作样式：
  - `重试` 或 `返回修改`
- 禁止项：
  - 原始堆栈和技术细节外露
- 中文文案注意事项：
  - 一定给下一步建议

## 24. LoadingState

- 视觉目的：
  - 让用户知道系统正在做什么
- 信息优先级：
  - 正在执行的动作 > 等待提示
- 推荐布局：
  - 骨架屏或轻量 loading 区
- 颜色语义：
  - 中性
- 状态样式：
  - loading
- 主动作样式：
  - 无
- 禁止项：
  - 纯空白 + 转圈
- 中文文案注意事项：
  - 要写“正在生成 Pulse”“正在识别导入内容”

## 总体视觉禁区

所有组件都不应：

- 伪装成真实发送或真实发布状态
- 使用高饱和大面积背景
- 让页面看起来像调试工具或后台系统
- 用颜色作为唯一状态表达方式
