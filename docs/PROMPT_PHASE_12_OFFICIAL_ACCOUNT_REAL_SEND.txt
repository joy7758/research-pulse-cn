Implement Phase 12 only: official-account real send v1.

Hard boundaries for this phase:
- Do not add WeChat OAuth login.
- Do not add Mini Program frontend code.
- Do not add customer-facing UI.
- Do not require live WeChat credentials for tests.
- Do not default-enable real sending in any environment.
- Do not turn official account publishing into a generic DeliveryJob channel.
- Do not implement a mass-broadcast / campaign engine in this phase.
- Do not weaken existing admin auth, internal service auth, sync device auth, or mini-read auth.
- Do not replace the current modular monolith architecture.

Primary goal:
Allow a deployment with valid WeChat official-account credentials to switch the provider from dry_run to real mode and perform credential-backed per-binding digest dispatch safely.

This phase should make the backend suitable for:
- explicit real provider activation in deployment environments
- access-token acquisition and caching
- real publication dispatch for a single bound official-account recipient
- sent/failed publication state transitions
- future expansion to richer official-account outbound strategies without refactoring the core

Architectural intent:
- Keep dispatch per binding / per recipient.
- Do not assume final marketing or broadcast strategy.
- Keep outbound transport pluggable.
- In v1, implement one concrete real transport strategy only:
  - template_notice
- Keep room for future strategies without breaking current models.

Required changes:

Extend provider settings with safe defaults.

Required settings:
- APP_OFFICIAL_ACCOUNT_PROVIDER_MODE with values [disabled, dry_run, real]
- APP_OFFICIAL_ACCOUNT_TRANSPORT_KIND with values [template_notice]

  - provider_mode = real

- document all settings clearly
- do not leak secrets in status endpoints
- if field mapping is absent, provide a production-friendly default mapping:
  - first
  - keyword1

2. Access token service and cache
Implement OfficialAccountAccessTokenService.

Requirements:
- use the official-account client-credential token flow
- cache token until shortly before expiry using refresh skew
- prefer Redis if already available cleanly in the project
- if Redis is unavailable in local/test, provide a simple in-process fallback cache
- do not persist raw access tokens to database tables
- do not log raw access tokens
- expose safe cache state in provider-status:
  - token_cached bool
  - token_expires_at nullable
  - last_refresh_at nullable
  - cache_backend summary
- add protected admin endpoint:
  - POST /admin/official-account/provider-token/refresh
- operator and super_admin can call it
- in dry_run mode this endpoint may no-op with a clear response
- in disabled mode it should not fake success

3. Real outbound provider and transport boundary
Add a real provider implementation.

Requirements:

- add RealOfficialAccountPublisher
- add a transport strategy boundary, for example:
  - OfficialAccountTransport

5. Real dispatch flow
Enhance existing dispatch endpoint behavior:
- POST /admin/digest-publication-jobs/{publication_job_id}/dispatch

Requirements:
- dispatch must support disabled, dry_run, and real modes
- disabled:
  - return controlled failure/conflict
  - create no fake success
- dry_run:
  - preserve current preview behavior
- real:
  - require provider readiness
  - require eligible publication job
  - require binding with:
    - channel_type = official_account
    - bind_state = active
    - subscribed = true
    - digest_enabled = true
  - create DigestPublicationAttempt
  - invoke RealOfficialAccountPublisher
  - on success:
    - mark publication job as sent
    - set published_at
    - store external_message_id if returned
  - on failure:
    - mark publication job failed
    - populate last_error
    - mark attempt failed
- dispatch idempotency:
  - if job is already sent and no force flag is provided, do not resend
  - optional force=false query parameter is acceptable
  - failed jobs may be retried deliberately
