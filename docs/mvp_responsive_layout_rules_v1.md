# MVP Responsive Layout Rules v1

## 目标

本文件定义 MVP 的响应式与布局规则，但不写 CSS。

## 总原则

### 1. Desktop-first

MVP 首先保证桌面端宽屏清晰，再做窄屏收敛。

原因：

- 主工作场景仍是桌面
- 论文阅读与进度管理更适合宽屏
- 小程序在本阶段仍只是 preview，不是独立前端

### 2. 先保证结构，不追求复杂响应式技巧

不要为了响应式引入：

- 多重复杂断点逻辑
- 过度动画
- 页面结构大幅重排

### 3. 保留“每页一个主动作”

无论宽屏还是窄屏，主动作都必须清楚。

## 断点策略

## `1440px+`

- 适用：
  - 设计主参考宽度
- 布局：
  - `LeftNav + MainContent + RightDrawer`
- 适合页面：
  - 首页
  - 论文进度页
  - Pulse 详情页

## `1280px`

- 布局：
  - 保持三层结构
  - Drawer 可略缩窄
- 要求：
  - 首页 cards 不应挤成拥挤多列

## `1024px`

- 布局：
  - `LeftNav` 可缩窄
  - `RightDrawer` 优先变成覆盖式抽屉
- 要求：
  - 主内容区仍是阅读中心

## `768px`

- 布局：
  - 导航可折叠
  - 主内容纵向排布
  - Drawer 默认覆盖式
- 要求：
  - 表格优先降级为卡片

## `narrow preview`

- 用途：
  - 预览未来小程序 detail 的窄屏阅读效果
- 规则：
  - 只做 preview 模拟
  - 不等于真实小程序页面实现

## LeftNav 折叠规则

- `1440 / 1280`：
  - 默认展开
- `1024`：
  - 可缩窄为图标 + 短文本
- `768`：
  - 可折叠到顶部按钮或抽屉

折叠后仍要保证：

- 当前页面清楚可见
- 一级导航不丢失

## RightDrawer 规则

- 宽屏：
  - 可与主内容并存
- 中屏：
  - 宽度缩小
- 窄屏：
  - 覆盖式抽屉

抽屉关闭后必须回到原列表上下文。

## 论文列表与详情关系

- 宽屏：
  - 列表在左，drawer 在右
- 中屏：
  - 列表为主，drawer 缩窄
- 窄屏：
  - 点击卡片后 drawer 覆盖全宽

## Payload preview 在窄屏下的处理

- 宽屏：
  - 可作为次级侧栏或下方面板
- 窄屏：
  - 必须下沉到折叠区或底部

规则：

- 不允许 payload preview 抢主内容
- 不允许在窄屏首屏先显示 JSON

## 小程序详情预览的窄屏模拟规则

- 窄屏预览用于验证：
  - 标题可读
  - card 纵向排列合理
  - share card 清楚
  - path placeholder 可复制

不用于模拟：

- 微信登录
- 支付
- 小程序原生 navigation

## 长论文标题换行规则

- 标题优先换行，不优先截断
- 首页卡片可限制 2 到 3 行
- drawer 和详情页应允许更多行

## 中文段落行宽规则

- 正文说明区不应过宽
- 说明文本应保持舒适阅读宽度
- 过宽时优先增加留白，而不是拉满整屏

## 表格在窄屏下的降级规则

- 导入预览表
- payload 预览列表

在窄屏下应优先降级为：

- 卡片列表
- 分组字段块

而不是强行保留宽表横向滚动作为唯一方案。

## 窄屏下主动作的固定规则

- 主动作始终可见
- 可以位于页面底部固定区或顶部状态区
- 次动作可以折叠，但主动作不能被埋没

## 响应式验收标准

1. 桌面端清晰优先。
2. 中屏不打乱信息层级。
3. 窄屏不丢失主动作。
4. 表格能降级成卡片。
5. 小程序详情 preview 在窄屏下依然清楚，但不伪装成真实小程序页面。
