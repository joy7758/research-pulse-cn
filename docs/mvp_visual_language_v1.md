# MVP Visual Language v1

## 目标

本文件定义 China-first Research Pulse MVP 的视觉语言方向。

它不负责说明前端如何实现，而是负责固定后续视觉决策的边界，避免前端把产品做成：

- 复杂后台
- 营销落地页
- 传统文献管理器
- 高噪音 SaaS dashboard

## 产品视觉关键词

本 MVP 的视觉气质应稳定围绕以下关键词：

- 简洁
- 干净
- 克制
- 科研感
- 可信
- 低干扰
- 高可读

这组词意味着：

- 用户进入后不会被视觉噪音打断
- 页面更像“科研工作台”，不是“运营后台”
- 重点内容被清楚突出，但没有夸张营销式视觉

## 视觉参考方向

## 1. ChatGPT 式单一主工作区

应该借鉴：

- 第一屏聚焦一个主任务
- 页面结构简单
- 大部分复杂度下沉到详情区或二级视图

不应照搬：

- 对话产品的开放式聊天气质
- 把所有页面做成聊天窗口

## 2. Paperpile 式干净文献列表

应该借鉴：

- 列表清楚、层级分明
- 工具区短而直接
- “整理文献”过程不压倒“推进研究”

不应照搬：

- 以文献列表为产品首页中心

## 3. Zotero 式成熟信息结构

应该借鉴：

- 题录信息、附件、标签、笔记的稳定层级
- 论文对象的结构完整性

不应照搬：

- 高密度三栏复杂感
- 默认专业型资料库界面

## 4. 中国科研工具的稳定可信感

中国科研用户更容易信任：

- 规整
- 清楚
- 没有花哨装饰
- 中文信息层级明确

因此视觉上应避免“新奇感优先”，而应追求“稳定感优先”。

## 不要采用的视觉方向

以下方向在 MVP 中都不应采用：

- 后台管理系统感
- 复杂 SaaS dashboard 感
- 强营销落地页感
- 大面积高饱和色
- 多层菜单和工具栏
- 过多按钮
- 过度强调图表化
- 大面积霓虹、渐变、玻璃质感装饰

## 页面气质定义

## 首页：轻量决策台

首页的视觉任务不是“展示功能”，而是“降低决策成本”。

首页应看起来像：

- 今日工作概览
- 重点事项摘要
- 下一步动作清单

不应看起来像：

- 论文数据库
- 报表中心
- 功能控制台

## 导入：低门槛确认流

导入页应看起来像一个友好的入口页：

- 空间足够
- 拖拽区明确
- 说明简洁
- 不让用户紧张

不应看起来像：

- 数据清洗后台
- 字段映射工具
- 技术运维页面

## 论文进度：清晰任务面板

进度页应看起来像：

- 可持续推进的研究列表
- 带状态与行动提示的卡片墙或轻列表

不应看起来像：

- 复杂管理表格
- 传统 ERP 列表

## Research Pulse：结构化科研摘要

Pulse 页应看起来像：

- 一份可执行的工作摘要
- 结构清楚、优先级清楚

不应看起来像：

- 内容资讯流
- 新闻推荐流

## 渠道草稿页：明确 `draft / not_sent`

公众号、桌面、小程序相关页面都应在视觉上第一时间强调：

- 这是草稿
- 这是预览
- 还没有真实发送

它们不应制造以下心理暗示：

- 用户需要立刻完成投递
- 已经发生了外部发送
- 已经连接到微信或系统通知

## 中文排版原则

## 1. 短句优先

按钮、标题、说明、提醒都应尽量短。

## 2. 动词明确

优先使用：

- 导入
- 刷新
- 查看
- 继续
- 补全
- 保存
- 复制

避免抽象名词堆叠。

## 3. 避免技术术语外露

用户主界面中应尽量避免：

- payload
- schema
- parser
- normalized
- contract

如果必须出现，应放在二级说明区，不进入首屏主文案。

## 4. warning 转建议

warning 的视觉和文案都应表达：

- 可继续
- 但建议处理

而不是：

- 失败
- 严重故障

## 5. error 转下一步动作

error 不能只停留在“失败”。

必须能引导用户：

- 返回修改
- 重试
- 查看问题记录

## 视觉情绪控制

本产品的整体情绪应是：

- 冷静
- 专业
- 平稳
- 值得信赖

不应是：

- 焦虑
- 过度警报
- 过度活跃
- 过度娱乐化

## 对后续实现的限制

Design-3 之后的前端实现必须继续遵守：

1. 首页是今日 Pulse，而不是论文库首页。
2. 重点信息靠层级和留白突出，不靠饱和颜色轰炸。
3. 草稿与预览必须显式展示，不能用“成功态”伪装。
4. 页面第一屏必须优先服务中国科研用户的当日任务推进。
