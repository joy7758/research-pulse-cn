Implement Phase 57 only: result share grant / alias conversion drilldown reserve v1.

Hard boundaries for this phase:
- Do not add source file sharing.
- Do not add local attachment sharing, note-file sharing, or cloud attachment sync.
- Do not add real-time collaboration or live multi-user editing.
- Do not add new delivery channels.
- Do not add desktop or mini UI work in this phase.
- Do not add a generic end-user login/session system.
- Do not add campaign/broadcast/referral behavior.
- Do not add third-party browser analytics scripts.
- Do not add AI attribution, AI summarization, or LLM-based conversion analysis.
- Do not create a new frontend app in this phase.
- Do not weaken existing auth boundaries.
- Do not replace the modular monolith backend architecture.

Primary goal:
Add read-only per-share drilldown APIs for:
1. ResultShareGrant
2. ResultShareAlias

This phase should make the repository suitable for:
- inspecting one share grant’s full read-only activity surface
- inspecting one alias’s access behavior and outcomes
- separating direct share-event attribution from direct collect linkage
- preparing a later admin per-share dashboard without exposing raw files

Architectural intent:
- Reuse existing persisted records only.
- Prefer no new persistence.
- Keep everything admin read-only.
- Keep share-grant drilldown and alias drilldown compact and operator-readable.
- No source-file semantics are exposed anywhere.

Required changes:

1. Prefer no migration
Do not add a new table unless absolutely necessary.
Prefer aggregating from existing sources:
- ResultShareGrant
- ResultShareAlias
- ResultShareViewEvent
- GroupWorkspaceResultCollectRecord

If a tiny additive index or nullable field is absolutely necessary, keep it strongly justified and backward-friendly.
Otherwise, no migration.

4. Admin endpoints
Add protected admin read-only endpoints:

Required:
- GET /admin/result-share-grants/{grant_id}/conversion-drilldown
- GET /admin/result-share-aliases/{alias_id}/conversion-drilldown

Behavior:
- operator and super_admin can read
- viewer access only if aligned with current read-only admin policy; otherwise restrict and document
- support reasonable filters where practical:
  - date_from
  - date_to
  - access_mode
  - event_type
  - outcome
  - limit for recent lists

5. Safe read models
Add read models such as:
- ResultShareGrantConversionDrilldownRead
- ResultShareAliasConversionDrilldownRead
- ResultShareAliasSummaryRead
- ResultShareRecentEventRead
- ResultShareDirectCollectRecordRead
- ResultShareAttributionScopeRead

Safety exclusions:
- no plaintext share tokens
- no plaintext aliases
- no raw IP
- no full referrer URL
- no raw user-agent
- no openid / unionid
- no local filesystem paths
- no local note contents
- no local attachment paths
- no source file contents

6. Attribution semantics
Be explicit and deterministic.

Requirements:
- share-event metrics are direct to the grant or alias when ids are present
- collect metrics are direct only when GroupWorkspaceResultCollectRecord.result_share_grant_id is present
- alias drilldown must not invent collect attribution if only grant-level linkage exists
- notes must clearly explain this distinction

- result-share-web remains unchanged in behavior
- group-workspace-admin-web remains unchanged in behavior
- group workspace overview/drilldown endpoints remain unchanged
