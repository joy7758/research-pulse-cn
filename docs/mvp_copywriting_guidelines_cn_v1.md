# MVP Copywriting Guidelines CN v1

## 目标

本文件定义 China-first Research Pulse MVP 的中文文案规范，保证后续页面、API 示例、demo script、草稿预览和错误提示的表达风格一致。

目标不是“写得更像技术系统”，而是“让中国科研用户一眼知道该做什么”。

## 文案总原则

### 1. 中文优先

用户可见文案优先中文。

允许保留英文的情况：

- API 字段名
- 文件名
- 导入格式名
- 技术文档中的 schema / endpoint 名称

### 2. 先说结果，再说原因

优先这样写：

- 已识别 12 条记录，其中 9 条可导入
- 今天有 2 篇高优先级论文需要处理
- 这条记录缺少年份，建议导入后补全

避免先给技术解释，再给结论。

### 3. 面向动作，而不是面向系统状态

更好的文案：

- 查看问题记录
- 确认导入
- 继续阅读
- 补全元数据
- 查看下一步动作

不好的文案：

- 进入解析结果管理
- 打开记录处理界面
- 执行状态更新流程

### 4. 短句优先

按钮、提示、标题尽量短，减少理解负担。

### 5. 不制造假象

如果只是草稿或预览，就必须明确说清楚。

## 空状态文案

### 首页空状态

- `今天还没有生成 Research Pulse，先导入论文或刷新一次。`

### 导入空状态

- `拖入 PDF、CSV，或粘贴 BibTeX / RIS / CSL JSON 开始导入。`

### 论文进度空状态

- `还没有论文进入这个分组。先导入，或去处理今天的重点论文。`

### 下一步动作空状态

- `当前没有待执行的下一步动作。可以从今日重点论文里补充一条。`

### 元数据待补全空状态

- `当前没有需要补全的元数据记录。`

### 新导入待筛选空状态

- `当前没有待筛选的新导入论文。`

## Warning 文案

### 适合保留为 warning 的场景

- 缺少年份
- 缺 DOI
- 缺来源
- 元数据可能重复
- 来自 PDF 文件夹占位导入，信息不完整

### 建议写法

- `这条记录缺少年份，仍可导入，建议后续补全。`
- `这条记录缺少 DOI，不影响导入，但会影响后续去重判断。`
- `该记录来自 PDF 文件夹占位导入，建议补全作者与年份。`
- `检测到同批次中可能存在重复记录，建议确认后再继续。`

## Error 文案

### 适合保留为 error 的场景

- 缺题名
- 格式无法识别
- 记录结构损坏
- `paper_id` 不存在
- 请求字段校验失败

### 建议写法

- `这条记录缺少题名，暂时无法导入。`
- `暂时无法识别这份内容的导入格式，请检查文件或粘贴内容。`
- `未找到对应论文，请刷新后重试。`
- `提交内容不完整，请检查必填字段后再试。`

## `draft / preview / not_sent` 文案

### 必须明确显示的状态

- `草稿`
- `预览`
- `未发送`
- `仅供复制或查看`

### 示例

- `当前是公众号摘要草稿，尚未发送。`
- `当前是桌面通知草稿，仅用于预览内容与 payload。`
- `当前是小程序详情预览，不代表真实小程序页面已发布。`

## 禁止使用的误导文案

以下文案在 MVP 阶段禁止出现：

- `已发送成功`
- `已推送成功`
- `已发布`
- `已同步到微信`
- `已登录微信`
- `已完成小程序投递`
- `系统已自动理解全文`
- `系统已阅读全文`

## 推荐术语

优先使用：

- 待读
- 略读中
- 精读中
- 已读
- 待筛选
- 待补全
- 下一步动作
- 今日重点论文
- 继续阅读与分析
- 元数据待补全
- 新导入待筛选

谨慎使用：

- parser
- normalized
- payload
- schema
- contract

这些词适合开发文档，不适合面向普通用户的主界面。

## 示例文案

### 导入预览

```text
已识别 12 条记录：
- 9 条可直接导入
- 2 条缺少年份，导入后建议补全
- 1 条缺少题名，暂不可导入
```

### 首页摘要

```text
今日建议优先处理 2 篇高优先级论文，其中 1 篇已有下一步动作。
```

### 论文卡片

```text
状态：精读中
优先级：高
下一步：整理方法部分，周五前发给导师
```

### 元数据提醒

```text
该记录来自 PDF 文件夹占位导入，缺少作者和年份，建议先补全元数据。
```

### 渠道草稿说明

```text
这是公众号每日摘要草稿，仅供复制和预览，尚未发送。
```

## 文案验收标准

后续任何用户可见文案都应尽量满足：

1. 一眼能懂。
2. 能直接采取行动。
3. 不误导用户能力边界。
4. 不要求用户理解技术术语。
