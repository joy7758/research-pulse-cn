# MVP Information Architecture v1

## 目标

本文件定义 China-first Research Pulse MVP 的信息架构，确保后续 wireframe、前端和多端接入都围绕同一套页面与对象关系展开。

本阶段只定义结构，不实现 frontend。

## 总体结构

MVP 应围绕一个极简科研工作台展开，而不是围绕传统文献库展开。

一级结构建议如下：

1. 首页：今日 Research Pulse
2. 导入
3. 论文进度
4. Research Pulse 详情
5. 公众号摘要草稿
6. 桌面通知草稿
7. 小程序详情预览
8. 设置

## 一级导航

建议一级导航顺序：

| 导航项 | 目标 | 说明 |
| --- | --- | --- |
| 今日 Pulse | 今日该做什么 | 首页入口，最重要 |
| 导入 | 把论文放进系统 | 简单三步导入 |
| 论文进度 | 看论文当前处于什么状态 | 工作台主列表 |
| 渠道草稿 | 看多端草稿 | 公众号、桌面、小程序 |
| 设置 | 必要配置 | 只放少量必要项 |

如果需要更收敛，可以把“渠道草稿”做成二级分组，而不是一级独立菜单。

## 首页：今日 Research Pulse

### 页面定位

首页必须是整个系统的主入口。

### 主要区块

1. 顶部概览
   - 日期
   - 生成时间
   - 刷新或重新生成入口

2. 今日重点论文
   - high / urgent
   - 有 next action 优先

3. 继续阅读与分析
   - 略读中
   - 精读中
   - reviewing / relevant

4. 下一步动作
   - 有明确 next action 的论文

5. 元数据待补全
   - 缺作者
   - 缺年份
   - 缺 DOI
   - 缺来源

6. 新导入待筛选
   - inbox / triage / unread

7. 快速导入入口
   - 拖入文件
   - 粘贴内容
   - 自然语言输入框

### 首页不应承担

- 全量论文管理表格
- 高级过滤器中心
- 复杂设置面板

## 导入

### 页面定位

把系统的复杂解析能力压缩成用户可理解的三步流程。

### 流程结构

1. 输入
   - 拖入文件
   - 粘贴 BibTeX / RIS / CSL JSON
   - 上传 CSV / TSV
   - 选择 PDF 文件夹

2. 预览
   - 总记录数
   - 可导入数
   - warning 数
   - error 数
   - 问题记录列表

3. 确认
   - 确认导入可提交记录
   - 查看问题记录

### 二级信息

- 展开单条记录详情
- 查看 warnings / errors
- 查看重复提示

## 论文进度

### 页面定位

把论文从“文献对象”转成“研究对象”。

### 默认视图

- 全部
- 待读
- 略读中
- 精读中
- 已读
- 待筛选
- 待补全
- 有下一步动作
- 高优先级

### 列表卡片字段

- 标题
- 作者 / 年份 / 来源
- 阅读状态
- 研究阶段
- 优先级
- 下一步动作摘要
- 元数据提醒

### 详情区字段

- 题录信息
- 阅读状态
- 研究阶段
- 优先级
- 下一步动作
- 笔记摘要
- 标签
- 元数据 warning

## Research Pulse 详情

### 页面定位

从首页的摘要进入更完整的结构化科研上下文。

### 区块

- 今日重点论文
- 继续阅读与分析
- 下一步动作
- 元数据待补全
- 新导入待筛选

### 设计要求

- 与首页 section 保持一致
- 支持进入单篇论文详情
- 支持进入下一步动作列表、待补全列表、待筛选列表

## 公众号摘要草稿

### 页面定位

展示给用户的不是发送系统，而是内容草稿。

### 主要区块

- 草稿标题
- headline / summary
- section 列表
- 复制 Markdown
- 复制纯文本
- payload preview

### 明确边界

- 状态必须显示 `草稿` / `未发送`
- 不展示真实发送按钮

## 桌面通知草稿

### 页面定位

展示本地提醒内容的短文本版本。

### 主要区块

- 标题
- 正文
- urgency
- badge_count
- actions
- deep link
- payload preview

### 明确边界

- 状态必须显示 `草稿`
- 不展示真实系统通知能力

## 小程序详情预览

### 页面定位

展示未来小程序详情页所需的结构化 preview。

### detail types

- `daily_pulse`
- `paper`
- `next_actions`
- `metadata_attention`
- `triage`

### 页面区块

- 标题 / 副标题 / 摘要
- cards
- items
- actions
- share card
- navigation
- path placeholder

### 明确边界

- 状态必须显示 `预览`
- 只展示 share-safe data
- 不展示微信登录、支付、订阅消息等未实现能力

## 设置

### 页面定位

MVP 设置页只保留必要设置，不做复杂后台。

### 可接受内容

- 时区
- 默认生成偏好
- 基础导入偏好
- 渠道草稿偏好

### 当前不应放入

- 复杂角色权限
- 微信 access_token 管理
- 小程序身份绑定
- 复杂通知订阅系统
- 运营后台配置

## 关键对象关系

```text
Import input
-> Import preview
-> Import commit
-> Paper progress item
-> Research Pulse draft
-> Official-account draft / Desktop draft / Mini-program preview
```

### 重要说明

- 用户不需要在主界面直接看到这条技术链
- 用户只需要看到：
  - 导入成功了什么
  - 今天该处理什么
  - 草稿能否继续使用

## 对后续 wireframe 的要求

Design-2 应在本信息架构基础上继续细化：

- 一级导航布局
- 首页 section 排布
- 导入页三步结构
- 论文进度列表与详情关系
- 渠道草稿页的最小信息层级
- 小程序详情预览的卡片结构
