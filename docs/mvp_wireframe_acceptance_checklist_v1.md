# MVP Wireframe Acceptance Checklist v1

## 目标

本清单用于验收 Design-2 以及后续任何 wireframe 稿、前端实现稿，确保它们仍然符合 China-first Research Pulse MVP 的产品边界。

## 首页与信息架构

- [ ] 首页首屏显示的是 `今日 Research Pulse`，不是复杂文献库。
- [ ] 首页首屏明确回答：
  - [ ] 今天该看什么
  - [ ] 哪些论文要处理
  - [ ] 下一步做什么
- [ ] 首页存在快速导入入口。
- [ ] 首页没有默认展示全量论文大表格。

## 页面主动作

- [ ] 每个页面只有一个主动作。
- [ ] 次动作数量受控，不与主动作抢注意力。
- [ ] 主动作对应当前页面最自然的下一步。

## 导入流程

- [ ] 导入流程是“拖入 / 粘贴 -> 自动识别 -> 预览 -> 确认导入”。
- [ ] 用户不需要先理解 CSL JSON / BibTeX / RIS / CSV / TSV 差异。
- [ ] 导入预览页先显示可理解统计，再显示问题记录。
- [ ] 导入完成页会把用户带回下一步，而不是停留在纯成功提示。

## 论文进度与详情

- [ ] 页面名称和文案更像“论文进度”，不是“论文管理后台”。
- [ ] 论文详情通过侧栏 / drawer 打开，不打断主流程。
- [ ] 详情侧栏允许更新阅读状态、研究阶段、优先级、下一步动作。
- [ ] 元数据问题被显示为可理解提醒，而不是技术错误栈。

## Research Pulse 与渠道草稿

- [ ] Research Pulse 详情页包含：
  - [ ] 今日重点论文
  - [ ] 继续阅读与分析
  - [ ] 下一步动作
  - [ ] 元数据待补全
  - [ ] 新导入待筛选
- [ ] 公众号页面明确显示 `draft / not_sent`。
- [ ] 桌面通知页面明确显示 `draft / not_sent`。
- [ ] 小程序详情页面明确显示 `preview / share-safe`。

## 状态语义

- [ ] 所有草稿页都明确显示 `draft / preview / not_sent`。
- [ ] 不出现“已发送成功”“已推送成功”“已发布”等误导状态。
- [ ] 空状态不是空白页，而是带下一步建议。
- [ ] warning 和 error 被清晰区分。

## 误导能力禁区

- [ ] 不出现真实发送、群发、素材上传等按钮或文案。
- [ ] 不出现真实推送、系统通知调用等文案。
- [ ] 不出现微信登录、支付、订阅消息、小程序码等文案。
- [ ] 不出现外部 LLM、外部网络、外部检索的能力暗示。

## 中文文案

- [ ] 中文优先。
- [ ] 按钮文案短、明确、可行动。
- [ ] 错误被翻译成建议。
- [ ] 用户不需要理解技术术语才能继续。

## 技术边界

- [ ] 本轮只有文档改动，没有 frontend 变更。
- [ ] 本轮没有 backend 变更。
- [ ] 本轮没有 migration 变更。
- [ ] 本轮没有 dependency 变更。
- [ ] 没有恢复 admin preset / report / print / registry 旧轨道。

## Design-2 通过标准

只有当以下条件同时满足，Design-2 才算通过：

1. 页面线框已覆盖首页、导入、进度、Pulse、公众号、桌面、小程序、设置。
2. 页面状态矩阵完整。
3. 组件清单完整。
4. 交互规则完整。
5. 所有 `draft / preview / not_sent` 边界清晰。
6. 所有 wireframe 仍然服务于“我们多做一百步，客户少走一步”。
